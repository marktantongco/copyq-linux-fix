The Problem

Why CopyQ Breaks on Ubuntu 26.04

Ubuntu 26.04 LTS is the first LTS with no Xorg session. GNOME 50 runs exclusively on Wayland — and blocks third-party clipboard managers by design.

🚫

No wl-data-control

GNOME's mutter compositor does NOT implement the Wayland clipboard protocol. This is a privacy-by-design decision — no third-party app can monitor clipboard events.

⚠️

PPA Stuck at v13

The official PPA is at v13.0.0. Version 16.0.0 with improved Wayland support and per-MIME OOM protection is only on Flathub via Flatpak.

⌨️

No Global Shortcuts

GNOME Wayland restricts global keyboard shortcut registration. CopyQ's built-in hotkey system doesn't work — we use GNOME custom shortcuts instead.

🖥️

No System Tray

GNOME removed legacy StatusNotifier tray support. CopyQ's tray icon won't appear without extensions. Keyboard shortcuts are the alternative.

The Solution

XWayland Bridge Architecture

CopyQ is forced through the XWayland bridge so it can monitor the X11 clipboard. Every other app stays on native Wayland for best performance.

Ubuntu 26.04 LTS (GNOME 50 / Wayland-only / No Xorg session) │ ├── Native Wayland Apps │ Firefox, GNOME Terminal, VS Code, LibreOffice │ Protocol: wayland (best performance, secure by design) │ Clipboard: private — no third-party API │ ├── XWayland Bridge (X11 compatibility layer, auto-started) │ Protocol: wayland → compositor, X11 → client apps │ │ │ ├── X11 Apps: Wine, old Qt5, legacy GTK2 │ │ │ └── CopyQ 16.0.0 (Flatpak, forced to XWayland) │ ├─ Monitors X11 clipboard bridge │ ├─ Clipboard portal permission granted │ ├─ GNOME shortcuts: Ctrl+Alt+V (toggle) │ └─ Autostart at login (3s delay) │ └── xdotool / xmacro → BROKEN on Wayland └─ Replacement: ydotool

Troubleshooting

Known Issues & Fixes

Common problems and their solutions for CopyQ on Ubuntu 26.04 Wayland.

📋

Misses some clipboard copies

Expected on GNOME. Native Wayland clipboard events may not always bridge to XWayland. Most day-to-day copies work — this is a GNOME design limitation, not a CopyQ bug.

⌨️

Shortcuts not working

Check Settings → Keyboard → Custom Shortcuts. Re-register with ./scripts/05-setup-shortcuts.sh

🪟

Blank / transparent window

Force XWayland rendering with flatpak override --user com.github.hluk.copyq --env=GDK_BACKEND=x11

🔄

Broken after system update

Re-run the full installer: ./install.sh or diagnose with ./scripts/diagnose.sh

Configuration

What Gets Installed Where

# ── System-wide: all apps get native Wayland ── ~/.config/environment.d/wayland.conf GDK_BACKEND=wayland # GTK apps QT_QPA_PLATFORM=wayland;xcb # Qt apps (Wayland, fallback X11) SDL_VIDEODRIVER=wayland # SDL games ELECTRON_OZONE_PLATFORM_HINT=wayland # Electron apps # ── CopyQ ONLY: forced through XWayland bridge ── ~/.local/share/flatpak/overrides/com.github.hluk.copyq QT_QPA_PLATFORM=xcb # ← X11 bridge, not Wayland GDK_BACKEND=x11 # ← X11 bridge, not Wayland # ── Autostart at login ── ~/.config/autostart/com.github.hluk.copyq.desktop X-GNOME-Autostart-Delay=3 # Wait for XWayland init
