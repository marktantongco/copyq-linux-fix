The Problem

Why CopyQ Breaks on Ubuntu 26.04

Ubuntu 26.04 LTS is the first LTS with no Xorg session. GNOME 50 runs exclusively on Wayland. And GNOME's compositor (mutter) deliberately blocks third-party clipboard managers.

🚫

No wl-data-control

GNOME's mutter does NOT implement the Wayland clipboard protocol. This is a privacy-by-design decision. No third-party app can monitor clipboard events on GNOME Wayland.

⚠️

PPA Stuck at v13

The official CopyQ PPA (ppa:hluk/copyq) is still at version 13.0.0. Version 16.0.0 with improved Wayland support and per-MIME OOM protection is only available via Flatpak/Flathub.

🔧

No Global Shortcuts

GNOME on Wayland restricts global keyboard shortcut registration. CopyQ's built-in hotkey system doesn't work. We use GNOME custom shortcuts as a workaround.

🖥️

No System Tray

GNOME removed legacy StatusNotifier tray support. CopyQ's tray icon won't appear without extensions. Shortcuts provide the alternative.

The Solution

XWayland Bridge Architecture

CopyQ is forced through the XWayland bridge (not native Wayland) so it can monitor the X11 clipboard. Every other app stays on native Wayland.

Ubuntu 26.04 LTS (GNOME 50 / Wayland-only / No Xorg) │ ├── Native Wayland Apps │ Firefox, GNOME Terminal, VS Code, LibreOffice │ Protocol: wayland (best performance, secure) │ Clipboard: private, no API │ ├── XWayland Bridge (X11 compatibility layer, auto-started) │ Protocol: wayland → compositor, X11 → apps │ │ │ ├── X11 Apps: Wine, old Qt5, legacy GTK2 │ │ │ └── CopyQ 16.0.0 (Flatpak, forced XWayland) │ Monitors X11 clipboard bridge │ Clipboard portal permission granted │ GNOME shortcuts: Ctrl+Alt+V (toggle) │ Autostart at login with 3s delay │ └── xdotool / xmacro → BROKEN → use ydotool instead

Troubleshooting

Common Issues & Fixes

Known problems and their solutions for CopyQ on Ubuntu 26.04 Wayland.

📋

Clipboard not capturing

Expected on GNOME. Native Wayland clipboard events may not always bridge to XWayland. Most day-to-day copies work. This is a GNOME limitation, not a CopyQ bug.

⌨️

Shortcuts not working

Check Settings > Keyboard > Custom Shortcuts. Re-run: ./scripts/05-setup-shortcuts.sh

🪟

Blank/transparent window

Force XWayland rendering: flatpak override --user com.github.hluk.copyq --env=GDK_BACKEND=x11

🔄

Broken after system update

Re-run the installer or diagnostics: ./install.sh or ./scripts/diagnose.sh

Configuration

What Gets Installed Where

# System-wide: all apps get native Wayland ~/.config/environment.d/wayland.conf GDK_BACKEND=wayland QT_QPA_PLATFORM=wayland;xcb SDL_VIDEODRIVER=wayland ELECTRON_OZONE_PLATFORM_HINT=wayland # CopyQ ONLY: forced through XWayland bridge ~/.local/share/flatpak/overrides/com.github.hluk.copyq QT_QPA_PLATFORM=xcb # X11, not Wayland GDK_BACKEND=x11 # X11, not Wayland # Autostart at login ~/.config/autostart/com.github.hluk.copyq.desktop X-GNOME-Autostart-Delay=3 # Wait for XWayland
