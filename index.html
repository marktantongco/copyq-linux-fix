Root Cause

Ubuntu 26.04 broke clipboard managers

The first Wayland-only LTS release removed critical clipboard protocols, leaving popular managers unable to function without workarounds.

GNOME 50 Wayland-Only

Ubuntu 26.04 ships GNOME 50 as its first LTS release with no Xorg session. All applications run under the Wayland compositor, breaking X11-dependent clipboard tools.

No wl-data-control

Mutter removed the wl-data-control protocol as a privacy decision. Qt clipboard managers cannot register for clipboard events without it — this is the core blocker.

PPA Stuck at v13

The official CopyQ PPA has not been updated past v13. The Flatpak build ships v16.0.0 with Wayland improvements that still need the XWayland bridge to function.

Implementation

The fix

Two environment variables force CopyQ through the XWayland compatibility layer, restoring full clipboard monitoring capability.

XWayland Bridge

Setting QT_QPA_PLATFORM=xcb forces Qt applications through the XWayland compatibility layer. Mutter still proxies X11 selections to Wayland clients, so CopyQ intercepts clipboard data through the X11 selection protocol.

Adding GDK_BACKEND=x11 ensures GTK applications within the CopyQ workflow also route through XWayland for consistent clipboard behavior across toolkits.

# Launch CopyQ via XWayland bridge QT_QPA_PLATFORM=xcb \ GDK_BACKEND=x11 \ copyq

Flatpak v16.0.0

The Flatpak build includes Wayland patches not present in the PPA. Install via Flathub and apply the XWayland environment override.

GNOME Shortcuts

Set Ctrl+Alt+V as the global hotkey in CopyQ preferences. GNOME handles this through XWayland key forwarding.

Autostart with Delay

A 3-second autostart delay ensures the XWayland bridge is fully initialized before CopyQ attempts clipboard registration.

Known limitations

Issue #3587: Closing the main window may stop clipboard monitoring on XWayland. Keep CopyQ minimized to the tray instead of closing the window to maintain clipboard access.

The GNOME Shell extension for native clipboard monitoring cannot work inside the Flatpak sandbox. This means the XWayland bridge approach is required regardless of installation method on GNOME 50.

Quick Start

Install

Two methods to get CopyQ running. The modular installer handles all configuration automatically — Flatpak, overrides, shortcuts, and autostart.

Clone and Run Recommended

# Clone and run the installer git clone https://github.com/marktantongco/copyq-linux-fix.git cd copyq-linux-fix ./install.sh

One-line Install Alternative

# One-line install curl -fsSL https://raw.githubusercontent.com/ marktantongco/copyq-linux-fix/main/install.sh \ | bash

Ecosystem

Tools and alternatives

The Wayland input landscape is evolving. These tools complement or replace CopyQ for specific use cases on Wayland-native desktops.

ydotool
Simulates input events at the kernel level using /dev/uinput. Works on Wayland without XWayland but requires root or uinput group membership for the ydotoold daemon. Alternative to xdotool for keyboard/macro simulation.
wl-clipboard
The standard Wayland clipboard CLI. Provides wl-copy and wl-paste for pipe-based clipboard operations. Suitable for scripts but offers no GUI, history, or management features.
CopyQ v17
Upstream is tracking native Wayland support. The v17 milestone may include a direct zwp-primary-selection implementation that removes the XWayland dependency entirely on compositors that support it.
