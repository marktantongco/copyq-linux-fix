CopyQ on Ubuntu 26.04 Wayland

CopyQ clipboard manager breaks on GNOME 50 because mutter removed the wl-data-control protocol. This is the fix.

# Run CopyQ through XWayland bridge QT_QPA_PLATFORM=xcb GDK_BACKEND=x11 copyq

Ubuntu 26.04 broke clipboard managers

GNOME 50 Wayland-Only

Ubuntu 26.04 ships GNOME 50 as its first LTS release with no Xorg session option. All applications run under the Wayland compositor.

No wl-data-control

Mutter in GNOME 50 removed the wl-data-control protocol as a privacy decision. Qt clipboard managers cannot register for clipboard events without it.

PPA Stuck at v13

The official CopyQ PPA has not been updated past v13. The Flatpak build ships v16.0.0 with Wayland improvements that still need the XWayland bridge to function.

The GNOME Shell extension for native clipboard monitoring cannot register from Flatpak sandbox. The XWayland bridge is the only working path for managed clipboard access.

The fix

XWayland Bridge

Setting QT_QPA_PLATFORM=xcb forces Qt applications through the XWayland compatibility layer. Mutter still proxies X11 selections to Wayland clients, so CopyQ intercepts clipboard data through the X11 selection protocol.

Adding GDK_BACKEND=x11 ensures GTK applications within the CopyQ workflow also route through XWayland for consistent clipboard behavior.

# Launch CopyQ via XWayland bridge QT_QPA_PLATFORM=xcb \ GDK_BACKEND=x11 \ copyq

Flatpak v16.0.0

The Flatpak build includes Wayland patches not present in the PPA. Install via Flatpak and apply the XWayland environment override.

GNOME Shortcuts

Set Ctrl+Alt+V as the global hotkey in CopyQ preferences. GNOME handles this through XWayland key forwarding.

Known limitations

Issue #3587: Closing the main window may stop clipboard monitoring on XWayland. Keep CopyQ minimized to the tray instead of closing the window.

The GNOME Shell extension for native clipboard monitoring cannot work inside the Flatpak sandbox. This means the XWayland bridge approach is required regardless of installation method.

Troubleshooting documentation

Tools and alternatives

ydotool
A command-line utility that simulates input events at the kernel level using /dev/uinput. Works on Wayland without XWayland but requires root or uinput group membership for the daemon.
wl-clipboard
The standard Wayland clipboard CLI tool. Provides wl-copy and wl-paste commands. Suitable for scripts but does not offer a GUI or clipboard history management.
CopyQ v17 outlook
Upstream CopyQ is tracking native Wayland support. The v17 milestone may include a direct zwp-primary-selection implementation that removes the XWayland dependency entirely.
