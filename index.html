CopyQ on Ubuntu 26.04 Wayland

Ubuntu 26.04 LTS is the first Wayland-only LTS release with no Xorg session available. CopyQ 16.0.0 from Flathub brings clipboard management back via the XWayland bridge.

The Problem

Three blockers prevent CopyQ from working out of the box

GNOME 50 on Ubuntu 26.04 LTS introduces breaking changes that stop clipboard managers relying on X11 or the wl-data-control protocol.

GNOME 50 Wayland-Only

Ubuntu 26.04 LTS is the first Wayland-only LTS — no Xorg session available. Every application must function under the Wayland compositor, with no fallback to X11.

No wl-data-control Protocol

GNOME 50 mutter does not implement the wl-data-control protocol for privacy reasons. Clipboard managers cannot intercept or manage clipboard contents natively on Wayland.

PPA Stuck at v13.0.0

The Launchpad PPA has not published CopyQ for 26.04 and is stuck at version 13.0.0. The latest release, CopyQ 16.0.0, is available from Flathub with improved Wayland support.

The Solution

Three components that make it work

This project combines XWayland bridge configuration, Flatpak v16 packaging, and GNOME keyboard shortcuts into a single automated installer.

XWayland Bridge

Forces CopyQ through the X11 compatibility layer. Sets QT_QPA_PLATFORM=xcb and GDK_BACKEND=x11. All other apps stay on native Wayland.

Clipboard Bridge

Flatpak v16.0.0

Latest CopyQ from Flathub. Includes per-MIME size limits, OOM protection, and improved Wayland support. The PPA is stuck at v13.0.0 and not published for 26.04.

GNOME Shortcuts

Custom keybindings registered via gsettings. Ctrl+Alt+V (toggle), Ctrl+Alt+Shift+V (menu). No native hotkey support on GNOME Wayland.

Known Limitations

Caveats of the XWayland bridge approach

These are known issues with no complete fix yet. Understanding them helps avoid confusion when clipboard monitoring stops unexpectedly.

Issue #3587: X11 Connection Drop

Clipboard monitoring may stop when CopyQ's main window is closed under XWayland. This happens because QT_QPA_PLATFORM=xcb can break the X11 connection lifecycle when the window is fully closed. Workaround: keep CopyQ minimized instead of closed, or use tray-only mode to avoid the window lifecycle issue entirely.

No Flatpak GNOME Extension

CopyQ's built-in GNOME Shell extension (CopyQ Clipboard Monitor) provides native clipboard monitoring, but it cannot be registered from inside a Flatpak sandbox. The extension requires access to GNOME Shell's D-Bus interface, which is not available to sandboxed applications. The XWayland bridge remains the only functional path.

Install

Get up and running in one command

Clone the repo, make the scripts executable, and run the installer. It handles system checks, Flatpak setup, environment configuration, and shortcut setup.

Recommended: Flatpak Installer

Recommended

Clone the repository and run the unified installer. It checks your system, installs CopyQ 16.0.0 from Flathub, configures the XWayland bridge, and sets up keyboard shortcuts.

Terminal
git clone https://github.com/marktantongco/copyq-linux-fix.git && \ cd copyq-linux-fix && \ chmod +x install.sh scripts/*.sh && \ ./install.sh

Alternative: Rootless .deb

For systems without Flatpak, download and install the rootless .deb package directly. This does not include automatic shortcut setup.

Terminal
curl -sSL https://github.com/marktantongco/copyq-linux-fix/\ releases/latest/download/copyq-linux-fix.deb \ -o copyq-linux-fix.deb && \ sudo dpkg -i copyq-linux-fix.deb

Uninstall

Remove all configuration, shortcuts, and Flatpak overrides. The Flatpak package itself is not removed.

Terminal
./install.sh --uninstall

Tools & Alternatives

Related tools for Wayland clipboard and input

Complementary tools that solve adjacent problems on Wayland, from keyboard simulation to native clipboard access.

ydotool

Keyboard simulation on Wayland via the uinput kernel interface. Replaces xdotool for automated typing and key injection. Works everywhere on Wayland because it talks directly to the kernel, not the compositor.

wl-clipboard

Native Wayland clipboard CLI tools: wl-copy and wl-paste. Access the Wayland clipboard directly from the terminal without any X11 bridge. Essential for scripts on Wayland systems.

Future: CopyQ v17

Upstream CopyQ is tracking native GNOME Wayland support via the wl-data-control protocol. The Wine project merged wl_data_device support in March 2025, which may unblock native clipboard monitoring for CopyQ on GNOME.
